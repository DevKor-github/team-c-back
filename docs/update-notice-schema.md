# 업데이트 공지 DB 배포 경계

`GET /api/notifications/version`의 기존 `CommonResponse<String>` 계약은 구버전 앱 호환을 위해 유지한다.
새 앱은 공개 API `GET /api/notifications/notices`를 호출한다. 응답의 `notices`는 공지 페이지에
표시할 공개 시각이 지난 공지 전체이며, 그중 `show: true`인 항목만 업데이트 팝업 후보로 사용한다.

최신 앱 버전은 DB가 아니라
`domain/notification/config/AppVersionConfig.java`의 `LATEST_APP_VERSION`으로 관리한다. `develop`
코드를 검증한 뒤 `main`으로 승격하면 같은 소스 값이 prod 이미지에 자동 포함된다. 앱 바이너리의
`kodaero/config/appVersion.js`와 함께 변경해야 한다.

현재 애플리케이션은 `spring.jpa.hibernate.ddl-auto=update`이므로 개발 환경에서는 엔티티 배포 시
`tb_update_notice`, `tb_update_notice_feature` 테이블과 인덱스가 자동 생성된다. 운영 환경에서는
애플리케이션 시작 시 DDL 변경에 의존하지 말고, 아래 변경을 검토한 버전 관리 migration으로 먼저
적용한 뒤 배포해야 한다.

- `tb_update_notice`: 제목, 설명, 공개 시각, 앱 버전, 팝업 노출 여부와 선택적 원문 링크를 저장한다.
- `tb_update_notice_feature`: 공지별 기능 문구와 표시 순서를 저장한다.
- `published_at <= 서버 현재 시각`인 행만 API에 공개된다.
- `show_popup=false`는 공지 목록에서 제거하지 않고 팝업 노출만 막는다.
- `docs/sql/2026-08-07-update-notice.sql`은 App Store 공개 버전 기록(1.0.1~1.1.4), 기존
  개인정보 처리방침 공지와 1.1.5 릴리스 공지를 DB로 이전하는 멱등 SQL이다. 과거 공지는
  `show_popup=false`, 1.1.5 공지만 `show_popup=true`로 저장한다.
- 1.1.5 공지는 포인트 상점, 인앱 사용 설문, 공지 목록/일회성 팝업, 텀블러 세척기 태그 순서,
  필수 업데이트 안내를 실제 배포 범위로 기록한다. 해당 API와 1.1.5 스토어 바이너리가 모두
  준비된 뒤 SQL을 적용해야 한다.
- 스키마 생성 뒤 dev/prod DB에 각각 적용한다. 이후 공지 문구와 `show_popup`은 DB에서 관리하며
  프런트에는 공지 사본을 두지 않는다.
- 새 테이블만 추가되므로 롤백 시 구버전 API에는 영향이 없다. 데이터 보존이 필요하면 테이블을
  삭제하지 말고 신규 API 트래픽만 이전 버전으로 되돌린다.

## 이관한 과거 기록

과거 업데이트 공지는 Apple App Store의 공개 버전 기록을 기준으로 이관했다. 앱 코드의 전체 Git
기록에 남아 있던 업데이트 팝업과도 대조해 App Store 설명에서 생략된 제공처·출처 안내와 세부
기능 문구도 보존했다. 실제 배포 버전과 코드 작성 당시 버전이 다른 경우 App Store 버전을 우선했다.

| 버전 | 공개 시각 (KST) | 기록 |
| --- | --- | --- |
| 1.0.1 | 2025-01-29 08:01:39 | iOS 정식 출시 |
| 1.0.2 | 2025-01-30 12:03:27 | 스토어 정보 변경 |
| 1.0.3 | 2025-02-03 04:37:01 | 건물 운영시간 추가 |
| 1.0.5 | 2025-06-15 20:34:18 | 건물 정보, 즐겨찾기, 배리어프리, UI 개선 |
| 1.0.8 | 2025-09-18 17:33:18 | 고연전 무료주점, 외부 음식점, 편의시설 추가 |

개인정보 처리방침 제·개정 공지는 기존 프런트의 `2026-02-25` 노출 시작일과 `2026-02-28`
개정일을 보존해 별도 1.1.4 공지로 이관했다. App Store 1.0은 릴리스 노트 본문이 없으므로 공지
행을 만들지 않았다.

Git 기록에는 1.1.5 전용 공지 문구가 없다. `9e6fa33f`에서 앱 버전만 1.1.4에서 1.1.5로
올렸고, 당시 프런트에는 1.1.4에서 사용한 공지가 그대로 남아 있었다. 따라서 SQL의 1.1.5 공지는
과거 문구를 재사용하지 않고 이번 1.1.5 실제 배포 범위로 새로 작성했다.
